## 0. Важно перед началом работы

- Backend и frontend код лежит на Google Drive (этот репозиторий), но
  **зависимости (venv, node_modules) живут локально на каждом компьютере**,
  не на Drive — см. `README.md` раздел "ВАЖНО". На новом компьютере сначала
  создать локальный venv/node_modules по инструкции в README, потом
  запускать `scripts/start.bat`.
- На **этом** компьютере локальные пути:
  - backend venv: `C:\Users\savva\Projects\YouTube Auto Studio-backend\.venv`
  - frontend: `C:\Users\savva\Projects\YouTube Auto Studio-frontend`
- Если стартуете backend вручную (не через `start.bat`) — **используйте
  PowerShell `Start-Process`, не git-bash/Bash-tool**: путь
  `...\YouTube Auto Studio-backend\...` содержит пробелы и дефис, из-под
  git-bash команда uvicorn падает молча (exit 127), а curl на /api/health
  при этом может отвечать от старого процесса — легко спутать "работает" с
  "не работает". Рабочий паттерн запуска:
  ```powershell
  $backendDir = "<repo>\backend"
  $venvPython = "$env:USERPROFILE\Projects\YouTube Auto Studio-backend\.venv\Scripts\python.exe"
  Start-Process -FilePath $venvPython -ArgumentList "-m","uvicorn","app.main:app","--host","127.0.0.1","--port","8000" -WorkingDirectory $backendDir -WindowStyle Hidden
  ```

## 1. LLM-провайдер (сценарии/анализ/перевод)

Мультипровайдерный клиент в `backend/app/core/llm.py` — переключатель
`LLM_PROVIDER` в `.env` (`claude` или `gemini`), единый интерфейс
`llm_client.complete()` для всех сервисов.

**Текущее состояние `.env`:** `LLM_PROVIDER=gemini`.

- **Gemini работает ТОЛЬКО под системным VPN** (трафик бэкенда, не браузера).
  Без VPN — `400 FAILED_PRECONDITION: User location is not supported`.
  Рабочие модели на бесплатном тарифе этого ключа:
  `GEMINI_MODEL=gemini-2.5-flash` (20 запросов/день),
  `GEMINI_MODEL_FAST=gemini-3.1-flash-lite` (500/день, стабильнее).
  НЕ работают (limit:0 на free tier): `gemini-2.0-flash`, `gemini-2.5-pro`,
  `gemini-3.1-pro`. `gemini-1.5-*` и `gemini-3-flash` сняты (404).
  Под VPN периодически бывают `503`/обрывы соединения — в `llm.py` есть
  авто-повтор (3 попытки) на транзиентные ошибки.
- **Claude — рабочий запасной вариант без VPN** (`ANTHROPIC_API_KEY` в `.env`
  валиден). Переключить: `LLM_PROVIDER=claude` в `.env`, перезапустить backend.

**Если генерация падает с ошибкой про регион/квоту** — см. эту секцию, не
гадать заново.

## 2. 3-шаговая генерация сценария (по одной теме)

Пользователь задаёт только тему — дальше пайплайн сам:

1. **ADAPT** — ИИ переписывает 3 базовых шаблона (английских) под тему/нишу
   канала → 3 готовых промта (можно посмотреть/поправить в форме "Новое
   видео" перед запуском).
2. **PREP** — бриф по адаптированному промту 1 + память канала (антиповтор).
3. **WRITE** — черновик сценария по промту 2 + брифу.
4. **HUMANIZE** — авто-аудит и чистовая правка по промту 3 (не критичная
   стадия: при сбое в финал идёт черновик).

Код: `backend/app/services/script_chain.py` (логика шагов),
`script_templates.py` (хранение шаблонов: дефолты в `app/prompts/chain/*.txt`,
пользовательские правки — в `data/templates/*.txt`, редактируются на странице
**Настройки** во фронтенде). Промежуточные артефакты (`prep.md`, `draft.md`)
пишутся в `data/projects/<id>/videos/<id>/pipeline/`.

API: `GET/PUT /api/templates`, `POST /api/templates/adapt`.

**Статус: готово и проверено** на обоих провайдерах (Claude и Gemini).

## 5. AI-визуальный ряд (САМОЕ СВЕЖЕЕ — добавлено в этой сессии)

Картинки по контексту сценария вместо статичной обложки, через **Replicate**.

### Как это работает
1. `image_gen.generate_image_prompts()` — ОДИН запрос к LLM: задаёт **единый
   визуальный стиль** на всё видео (медиум, палитра, свет) + разбивает
   сценарий на N сцен (по одной на `VISUAL_SEGMENT_MINUTES` минут видео, капа
   `VISUAL_MAX_IMAGES`). Жёстко требует:
   - **тёплая пастельная палитра** + **лучшее качество** на каждой картинке
     (это зашито И в промт для LLM, И отдельным хардкодным суффиксом —
     `_QUALITY_SUFFIX` в `image_gen.py` — независимо от того, что решит LLM);
   - **только общие/широкие планы** везде (никаких внезапных макро/портретов
     посреди серии общих планов — единая "экспозиция кадра");
   - если канал/тема историческая — **строгая историчность**, без современных
     объектов/одежды/техники.
2. `image_gen.generate_image()` — каждая сцена уходит в Replicate
   (`black-forest-labs/flux-schnell`, ~$0.003/картинка). Поддержан опциональный
   img2img-референс на первую картинку (`VISUAL_USE_REFERENCE=true` в `.env`,
   нужна модель с поддержкой image, например flux-dev — schnell не умеет,
   автооткат на text-only). Общий `seed` на всё видео для стабильности палитры,
   когда референс выключен.
3. `image_gen.upscale_image()` — апскейл через Replicate
   (`nightmareai/real-esrgan`, ~$0.002-0.004/шт) до Full HD+. Включено по
   умолчанию (`VISUAL_UPSCALE=true`). **Проверено вживую: 1344×768 →
   2688×1536.** Не критично — при сбое картинка остаётся в исходном размере.
4. Рендер (`video_builder.render_video_segments`) — Ken Burns (очень
   медленный зум, было агрессивно — поправлено), тёплый цветокор всегда
   (`colorbalance` + лёгкая пастельность), **опциональные частицы**
   (тёплые мерцающие огоньки/искры, `particle_gen.py`, кешируются один раз,
   накладываются screen-блендом). Переключатель частиц — чекбокс в настройках
   канала (`Project.particles_enabled`, по умолчанию **выключено**).

### Где в UI
- Видео → блок **«Визуальный ряд (AI)»**: галерея картинок, клик открывает
  **лайтбокс** (стрелки/Esc, показывает промт), кнопка
  «Сгенерировать/Перегенерировать» (= `POST /stages/visuals`).
- Настройки канала → чекбокс **«Частицы (огоньки/искры) на видео при
  рендере»**.

### Rate-limit Replicate — важно
Аккаунт ограничен **6 запросов/мин на создание предсказаний**. В
`pipeline._stage_visuals` между КАЖДЫМ вызовом Replicate (генерация картинки
+ отдельно апскейл) — пауза **11 секунд**. С апскейлом включённым на видео из
N картинок уходит ~22 сек/картинку. Плюс авто-повтор в `image_gen.py` на
`429`/SSL-обрывы/таймауты (типичны под VPN). **Не убирайте паузы** — без них
сразу ловите `429 throttled`.

### Текущий токен Replicate
Актуальный токен — в `.env` (не в git). Текущий — второй по счёту, первый был
отозван Replicate и давал `401 Unauthenticated`. Баланс проверяйте на
**replicate.com/account/billing**, токены — **replicate.com/account/api-tokens**.

### Статус: готово и проверено
- Полная цепочка генерации картинок — проверена живым прогоном (7/7 картинок,
  один общий стиль, период-аккуратные сцены для исторического канала).
- Апскейл — проверен живым вызовом.
- Ken Burns + частицы — проверены реальной сборкой FFmpeg (с частицами и без).
- 8/8 backend pytest проходят.
- Frontend собирается чисто, синхронизирован в Drive-бэкап.
- Миграции БД применены: `videos.voice_overrides`, `videos.script_prompts`,
  `projects.particles_enabled` (см. `core/database.py` → `_NEW_COLUMNS`).

## 5.5. Монтаж и публикация (сессия 2026-07-11)

Панель «Параметры монтажа» (VideoView → карточка «Готовое видео»)
сохраняется в `videos.render_params`, рендерит `video_builder.py`:

- **Камера**: Выкл / Приближение (зум строго в центр кадра) / Отдаление /
  Чередование / **Панорама** (боковой дрейф, направление чередуется по кадрам).
- **Скорость зума** — ползунок 0.05–2 %/с (0.3 по умолчанию — очень медленно);
  для панорамы скорость фиксированная.
- **Цветокор**: Тёплый / Без / Холодный / Винтаж / Ч‑Б (`grade` в render_params;
  старый `warm_grade` bool поддержан для совместимости).
- **Огоньки** (оверлей частиц, `particle_gen.py`, бесшовный луп 10 с):
  Светлячки / Искры огня / **Пыль** (тусклые пылинки — для sleep-контента).
  Выбор per-video (`overlay`); чекбокс канала — только дефолт.
- **Переход**: Резкий / Затемнение (dip) / Кроссфейд (xfade, длительность
  компенсируется — итоговая длина = длине аудио). Плюс fade in/out всего видео.
- **Качество**: CRF 18, lanczos-скейл, холст с запасом 1.25 — zoompan никогда
  не апскейлит (нет «мыла»); зум капится тем же запасом.
- **Превью монтажа**: кнопка в панели → `POST /api/videos/{id}/preview-render`
  → 12-сек ролик без звука из первых 3 картинок с текущими параметрами
  (файл `preview_montage.mp4` в папке видео). Проверено вживую.

Публикация и субтитры:
- **Пакет YouTube**: `GET /api/videos/{id}/youtube-package` — заголовки,
  описание (hook + summary + key points), теги (обрезка до 500 симв.).
  Карточка «Публикация на YouTube» в табе основного языка, кнопки «Копировать».
- **Субтитры**: `GET /api/videos/{id}/subtitles/{lang}` — .srt с
  ПРИБЛИЗИТЕЛЬНЫМИ таймингами (по предложениям, пропорционально словам,
  относительно длительности аудио). Кнопка «.srt» в карточке Аудио.
  Точные тайминги через faster-whisper — в планах.

Пакетная генерация:
- Чекбокс «Пакетный режим» в форме «Новое видео»: каждая строка поля темы —
  отдельное видео. Пайплайны выполняются ПО ОЧЕРЕДИ — глобальный семафор
  `_PIPELINE_QUEUE` в `pipeline.py` (ожидающие видео висят в статусе draft).

Прочее:
- `.claude/launch.json` переписан на PowerShell (cmd ломался на кавычках).
- Известный артефакт: если backend убить некрасиво, сокет 8000 может унаследовать
  дочерний процесс `multiprocessing.spawn` (Python312) — убивать его.

Идеи на будущее (выписаны, не реализованы): faster-whisper субтитры, стоковое
видео Pexels, экспорт/импорт проекта архивом, прямая загрузка на YouTube (OAuth),
семантический поиск памяти при 200+ видео, оценка стоимости перед запуском.

## 6. Известные грабли (чтобы не наступать снова)

1. **Дубли строк в `.env`** — однажды было два `REPLICATE_API_TOKEN=` (одна
   пустая, одна с ключом). Последняя строка выигрывает при парсинге, но это
   путает при ручной правке. Проверяйте `grep -n KEY= .env` при сомнениях.
2. **Backend не подхватывает новый `.env` без перезапуска процесса** —
   настройки кэшируются (`lru_cache`) на весь процесс. После правки `.env`
   ВСЕГДА перезапускать backend.
3. **Запуск backend через Bash-tool (git-bash) на путях с пробелами молча
   падает** (exit 127) — использовать PowerShell `Start-Process`, см. §0.
4. **`style_prompt` канала в выводе терминала может показываться
   кракозябрами** при кодировке консоли — в самом приложении (UTF-8) это не
   баг, просто артефакт вывода в Windows-консоли при чтении кириллицы.
